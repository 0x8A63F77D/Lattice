裁决:功能标记维持 (a) cap band,图例色块按 cap height 消解

依据:REQUEST.md、README(实验室走查)、measurements.tsv 全量数据、14 张 montage 的目检,以及本页三端 × 八款字体的实机实测。已拍板并写入 RULING.md(进 repo、供 gate 断言引用)。

R1 · 功能标记
方案 (a):cap band,t = 0

带 = 大写顶 → 基线。所有平台习语尺寸的标记(12px 状态图标、16px 播放、20px checkbox)一律取该带中心。两标记按钮共用标签的同一条带。代价明码:有下沉笔画的拉丁标签最差偏高 1.55 DIP;换来 script 无关与双语列齐平。

R2 · 图例色块
消解:size = cap height,radius 2

色块高=宽=标签字体 cap height,顶底与 cap band 重合——(A)(B) 两种哲学在此重合,误差按构造为 0,对用户数据的下沉笔画完全免疫,且恰好就是 Fluent 明文的 cap 规则。圆角裁定为 2(= borderRadiusSmall token),sample 见下。

R3 / R4 · 例外与范围
无站点例外

图例无需另立例外——它唯一的标记是色块,已由 R2 裁定。纯数字格保持数字带,四方案下本就不动,合同里只作重述。20px checkbox 由 R1 通用覆盖并点名一次,不另立规则。

理由(含对 Fluent 合规的交代)

  • (a) 是 Fluent 的字面机械化,代价明码接受。cap band 就是 optically center 的默认实现。Lattice 约一半拉丁标签带下沉笔画,(a) 在这一半上偏高 1.31–1.55 DIP;落选的 (d)(t=0.5)能压到 0.82。仍选 (a):它是唯一无需 script 分支的规则,且两者机制同构、gate 形状相同,改判只需翻一个常数。
  • 中文与双语是决定性的一票。汉字无下沉笔画,(d) 的补偿对 CJK 是纯损失:五款 CJK 字体实测 (a) −0.50…0.00、(d) +0.25…+0.75 DIP。同列中英图标台阶:(a) 0.00、(d) 0.25、按 script 分流 0.50 DIP——只有 (a) 保证混排列绝对齐平。
  • (b)(c) 排除,与实验室同判。(c) 在 14 个位置中 11 个顶到上限、与 (b) 无异,且在两标记按钮上不可表达;(b) 让事件日志徽章长高 ~1px,并把误差原样推给另一半词。
  • 图标字体已排除嫌疑。Fluent 图标字形的墨迹中心正好落在 12px 盒子中心(偏移 0.00),与文本字体混排不引入任何隐藏常数,以上数值全部可信。

    色块消解让图例退出赌局。README 发现 3:项目名是用户数据,@ 的下沉在两种字体间翻转。R2 之后色块位置只依赖 cap 度量,与词的墨迹无关,两字体下按构造 0 误差(实测已验证:位置与尺寸无关,0.000)。

合同正文预览(英文,定稿即此文本进 RULING.md)

RULING #206 — chrome-mark vertical alignment Status: FINAL — 2026-08-02 R1. Functional marks (any mark whose size is platform idiom, incl. 12 px status icons, 16 px play, 12 px chevron, 20 px checkbox): Philosophy (A) — optical centre on a fixed reference band, t = 0. bandTop = baseline − capHeight bandBottom = baseline centerY(mark) = baseline − capHeight / 2 capHeight is a FONT METRIC at the label's resolved size — never per-string ink, so the band is invariant under text, locale and user data. A label seating multiple marks centres every mark on that same band. GATE: |centerY(mark) − centerY(band)| ≤ 0.05 DIP on arranged layout geometry, at every registered site, in every registered UI font. Registered UI fonts Latin, pinned in tests : Inter Latin, macOS runtime : Helvetica CJK, macOS : PingFang SC CJK, Windows : Microsoft YaHei, Microsoft YaHei UI (distinct families, distinct vertical metrics — register both, not as one) CJK, Linux : Noto Sans SC OPEN — blocks gate coverage, not the ruling: 1. Latin runtime faces on Windows and Linux were never measured. The lab covered macOS runtime (Helvetica) plus the pinned test font (Inter). Register and measure whatever the Windows and Linux stacks actually resolve for Latin labels before claiming three-platform gate coverage. R1 is unaffected in form: t = 0 reads capHeight from whichever face resolves, so adding faces is mechanical. 2. PingFang SC figures come from a third-party webfont subset. Want one confirmation run on real macOS hardware. R2. Statistics legend swatch (decorative; the one mark whose size is open): swatchHeight = swatchWidth = capHeight(label font, resolved size) swatchTop = baseline − capHeight; swatchBottom = baseline cornerRadius = 2 (= borderRadiusSmall) Note: philosophies (A) and (B) coincide here by construction; position is independent of label descender content and of font choice. GATE: swatch edges equal cap-band edges ± 0.05 DIP; radius == 2. R3. Digit-only cells (deadlines, RAC) keep the digit band. No change; restated so the gate's site registry is exhaustive. R4. Site exceptions: NONE. The legend needs no descender exception because its only mark is the swatch, ruled by R2. Falsification: t = 0 is optimal for a repertoire in which descender-free and CJK labels dominate, and for any UI mixing scripts in one column. If the repertoire becomes predominantly Latin AND descender-carrying, AND mixed-script columns are eliminated, re-run the alignment lab; t = 0.5 then dominates and R1 is re-ruled by flipping the single constant.
